# Модель угроз `vn-vertical-engine`

Статус: действующий контракт безопасности.

Документ описывает фактические границы защиты официального runtime и инструментов
проекта. Он применяется к автономному запуску через `file://` и к статическому
размещению по HTTP(S). Правила сообщения об уязвимостях находятся в
[SECURITY.md](../../SECURITY.md).

## Цели защиты

Проект стремится обеспечить следующие свойства:

1. Данные авторских `story.js` и `story360.js` проверяются перед использованием.
   По умолчанию их JS выполняется в странице и считается доверенным; изоляция
   DOM доступна только в сохранённом Worker-режиме. Его ограничения побочных
   API неполны; известные обходы описаны ниже.
2. Пути авторских ресурсов не могут выйти за `assets/`, превратиться во внешний
   URL или скрыть обход через кодирование и нестандартные разделители.
3. HTML-мини-игра не получает DOM, хранилище и навигационные возможности
   родителя, а результат принимается только от текущего iframe и текущей сессии.
4. Панорамный пакет не выполняет JavaScript и проходит проверку структуры,
   размера и бинарных метаданных до передачи изображения в WebGL.
5. Повреждённое или подменённое автосохранение не становится исполняемым кодом и
   не восстанавливает неизвестную сцену или несовместимую структуру.
6. Публичный релиз собирается из ожидаемого состава, проходит тесты и получает
   проверяемые контрольные суммы.

Защита конфиденциальности опубликованного клиентского кода, сценария и медиа не
является целью: пользователь устройства может читать доступные браузеру файлы.

## Границы доверия

| Компонент или вход | Доверие | Пояснение |
| --- | --- | --- |
| `index.html`, `engine/*` | Доверенные | Выполняются с полномочиями основной страницы и задают границы sandbox |
| Официальные `lib/*` | Доверенные сторонние компоненты | Выполняются в основной странице; версии и SHA-256 закреплены в `dev/dependencies.json` |
| `license-key.js` | Доверенная локальная конфигурация | Подключается как обычный script и поэтому не должен поступать из недоверенного проекта |
| `user.js` и подключённые им сервисы | Доверенный авторский код | Выполняются в основной странице с доступом к DOM, хранилищу и сети; не изолируются Worker-режимом сценариев или sandbox игр. Учебный `user-example.js` сам не подключается и не отправляет данные |
| Официальные инструменты и release workflow | Доверенные программы | Их выбранные каталоги, архивы и импортируемые файлы остаются недоверенными входами |
| `story.js`, `story-example.js`, `story360.js` | Доверенный исполняемый ввод в режиме direct | По умолчанию выполняются обычными script в странице; изоляция действует только при явном выборе worker |
| HTML-мини-игры | Недоверенный активный ввод | Строгий sandbox, CSP игры и родителя, отзыв сессии при повторном load; полная изоляция сети и вычислений не гарантируется |
| `*-360.css` | Недоверенный декларативный ввод | Читается как текст либо через ограниченный CSP fallback и разбирается строгим парсером |
| Обычные изображения, SVG, аудио и видео | Недоверенные данные | Допускаются по пути и расширению; для студенческих проектов дополнительно проверяются аудитором |
| URL-параметры, `postMessage`, `localStorage` | Недоверенные данные состояния | Нормализуются и проверяются перед влиянием на runtime |
| Каталог студенческого проекта и релизный ZIP | Недоверенные наборы файлов | Проверяются allowlist, анализатором и тестами состава без признания содержимого доверенным |

Замена доверенного файла модифицированной копией переносит его за эту границу.
Проверки входных данных не предназначены для защиты от уже скомпрометированного
`engine.js`, библиотеки, браузера или ОС.

## Обычное подключение сценариев и сохранённый Worker

В `index.html` по умолчанию установлен `STORY_SCRIPT_LOAD_MODE = "direct"`:
сценарии последовательно подключаются обычными `<script>` для совместимого
автономного запуска. Этот режим выбран после отказа Worker-импорта локальных JS
в Chrome 152. Авторский код получает права основной страницы, включая DOM и
доступные сетевые API; валидатор данных не является границей исполнения.
Синхронный бесконечный цикл такого скрипта нельзя остановить таймаутом загрузчика.

Режим `"worker"` сохранён и включается только явным изменением константы в
доверенном `index.html`. Ошибка Worker не включает прямое выполнение автоматически.
Дальнейшие гарантии изоляции в этом разделе относятся только к Worker-режиму.

`engine/story-sandbox-loader.js` создаёт отдельный Worker для каждого
`story.js` или `story360.js`. Единственный исходный файл загружается сохранённой
до изоляции ссылкой на `importScripts`; обычное обращение к глобальному имени
`importScripts` вызывает замену, которая отклоняет вложенную загрузку.

До запуска авторского файла Worker скрывает:

```text
fetch
XMLHttpRequest
WebSocket
EventSource
WebTransport
Worker
SharedWorker
BroadcastChannel
indexedDB
caches
importScripts для вложенных файлов
```

**Известное ограничение от 2026-09-02:** эти подмены не являются полным запретом
побочных действий. В реальных браузерах динамический `import()` отправил
внешний запрос; через цепочку прототипов удалось восстановить исходные `fetch`
и `importScripts`, выполнить запрос и вложенный импорт. В прототипах также
сохраняются getter для `indexedDB` и `caches`; их доступность не означает, что
конкретный непрозрачный origin разрешит операцию с хранилищем.

Для запрета сети перед возвратом Worker-режима нужен ограничительный CSP для
скриптов и соединений, а подмены API требуют усиления с учётом прототипов.
Эксперимент с CSP блокирует проверенный динамический импорт, но эта политика
ещё не встроена в runtime. Результаты и команды повторения находятся в
[исследовании загрузки сценариев](../../dev/research/story-worker/README.md).

Worker не имеет DOM. Результат возвращается через `MessagePort`, сохранённый в
замыкании bootstrap и недоступный пользовательскому скрипту. После результата,
ошибки или таймаута в 10 секунд Worker завершается и его Blob URL отзывается.

Для `STORY_TEXT` действует предел 8 МиБ. `STORY360` обязан иметь `version: 1` и
объект `spaces`; внутри Worker строится JSON-подобная копия с нулевыми
прототипами. Отклоняются циклы, функции, неизвестные прототипы, неконечные числа,
ключи `__proto__`/`prototype`/`constructor`, глубина больше 64, более 250 000
узлов, строка больше 4 МиБ и суммарные строки больше 16 МиБ. Сохранённые до
запуска встроенные функции не позволяют сценарию ослабить валидатор их подменой.
Та же фабрика валидаторов используется после обычного script в режиме direct;
она проверяет результат, но не отменяет побочные эффекты уже выполненного кода.

Остаточный риск: формат остаётся JavaScript. До валидации файл способен выполнять
вычисления и выделять память внутри Worker. Таймаут останавливает зависший поток,
но не гарантирует предотвращение кратковременного исчерпания памяти устройства.

## Пути ресурсов

`engine/resource-path-policy.js` принимает только канонические относительные пути
внутри `assets/`. Запрещены внешние и абсолютные URL, `..`, обратные слеши,
query/hash, percent-encoding, управляющие символы, чрезмерная длина и расширение,
не соответствующее типу ресурса. Runtime повторно проверяет путь перед созданием
URL, даже если сценарий уже прошёл парсер.

Allowlist расширений не доказывает безопасность произвольного содержимого файла.
Официальный аудитор поэтому отдельно проверяет состав студенческого проекта,
SVG, HTML-игры и панорамные пакеты. Он уменьшает риск, но не является доказательством
отсутствия уязвимостей браузерного декодера или сложного активного содержимого.

## HTML-мини-игры и `postMessage`

Перед каждым явным запуском runtime заново устанавливает iframe
`sandbox="allow-scripts"`, `referrerpolicy="no-referrer"` и Permissions Policy.
Не выдаются `allow-same-origin`, popup, downloads, top navigation, формы, камера,
микрофон, геолокация, USB и другие чувствительные возможности. Одновременно
существует не более одной активной игровой сессии.

Sandbox изолирует игру от DOM и origin родителя, но сам по себе не запрещает все
сетевые запросы. Поэтому каждая автономная игра обязана содержать строгий meta
Content-Security-Policy из `docs/specs/spec-game.md`, включая
`connect-src 'none'`, `frame-src 'none'`, `object-src 'none'`,
`worker-src 'none'`, `form-action 'none'` и `base-uri 'none'`. Аудитор проверяет
этот профиль по исходнику; тестер нужен для проверки выполнения перед публикацией.

При строгом sandbox iframe имеет непрозрачный origin, а при `file://` фиксированный
origin также непереносим между браузерами. Поэтому `gameInit` и `gameResult`
отправляются через `postMessage(..., "*")`. Доверие не строится на строке origin:
runtime требует точное совпадение `event.source` с `contentWindow` активного
iframe, `gameId`, непредсказуемого `sessionId` и поддерживаемой явной версии
протокола, если она передана. Результат одной сессии принимается только один раз.

Текущий runtime временно принимает результат существующей игры v2 без поля
`protocolVersion`, если источник, `gameId` и `sessionId` совпали. Новые игры по
спецификации обязаны возвращать `protocolVersion: 2`; неизвестная явная версия
всегда отклоняется.

Параметры `gameInit` доступны коду игры и не должны содержать секреты. Прямое
открытие недоверенного HTML вне iframe движка снимает перечисленные ограничения.

**Усиление от 2026-09-02:** host отправляет `gameInit` только на первый `load`
явного запуска. Каждый запуск получает новый iframe, настроенный до вставки в
DOM: события старого документа и его промежуточного `about:blank` не относятся
к новой сессии. Тестер также заменяет iframe при явной загрузке.
Повторный `load` сначала отзывает сессию и очищает iframe, затем
восстанавливает UI. Это действует также после принятого результата URL-игры.
Сюжет продолжается с `0`, как после ручного закрытия; статистика остаётся на
каталоге; URL-режим показывает ошибку до ручного перезапуска. Тестер запрещает
выдавать `gameInit` новому документу до явной загрузки кнопкой и отменяет
отложенную автоматическую отправку предыдущего запуска.

В `index.html` до ресурсов установлен meta CSP
`frame-src 'self' file: blob: data:`. Он сохраняет локальные игровые документы,
свой origin при HTTP(S) и служебные iframe CSS-панорам, но запрещает внешние
документы iframe. Собственный CSP каждой игры по-прежнему обязателен:
родительский `frame-src` не ограничивает все сетевые API дочернего документа.

Это защита от повторной выдачи параметров, а не полная идентификация документа:
`WindowProxy` и `event.source` сохраняются при навигации. Обработчик `load` не
предотвращает начало перехода, редирект до первой загрузки или намеренную передачу
игрой уже известных ей параметров. Внешний документ блокирует CSP родителя;
переходы среди разрешённых им адресов не получают отдельного доказательства
происхождения. Поэтому в `gameInit` нельзя передавать секреты.

В тестере ограничение origin документов отложено: он позволяет явно открыть
произвольный URL для разработки, и общий `frame-src 'self'` сломал бы этот режим.
Тестер не является средой исполнения заведомо враждебных HTML. Автоматическая
повторная инициализация после навигации запрещена и в нём.

Составное обращение к `location` прошло текстовый аудитор без замечаний.
Статические проверки не доказывают безопасность произвольного JS, а sandbox не
даёт переносимой гарантии отдельного потока: ограниченный цикл строгой игры
задержал родительский таймер в Firefox. Полный запрет сети и гарантированное
прерывание зависшей игры средствами основного окна не заявляются. В Firefox
перехват теста видел запрос внешнего документа до окончательного отказа CSP;
это не доказывает отправку пакетов и не доказывает блокировку до сетевого запроса.
Исходное воспроизведение, внедрённые меры и результаты
для Chrome/Chromium/Firefox описаны в
[исследовании HTML-игр](../../dev/research/html-games/README.md).

## Автономные 360-панорамы

Runtime принимает панорамные изображения только как декларативные
`*-360.css`; исторические `*-360.js` не подключаются и не выполняются. Основной
путь читает CSS как текст в отдельном iframe и допускает только комментарии и
одно каноническое правило `#vn360-pack`. `@import`, дополнительные правила,
CSS-escape, неизвестные и повторные свойства отклоняются.

Из-за закрытого локального origin Chromium/Edge только при `file://` допускается
запасной iframe с nonce-CSP и единственным `<link>`. Сеть, скрипты, изображения,
шрифты и вложенные ресурсы в нём запрещены. После чтения известных custom
properties применяются те же проверки метаданных и бинарного содержимого.

Исходный CSS ограничен 130 МиБ, Base64 — 128 МиБ, декодированное изображение —
96 МиБ, пакет — 4096 частями по 32 КиБ. Допустимы PNG/JPEG/WebP не более
`20000 × 15000` и 300 000 000 пикселей; реальные размеры из бинарного заголовка
должны совпадать с метаданными. Blob URL, временные iframe и старые WebGL-текстуры
освобождаются после использования.

Полное обоснование и ограничение совместимого Chromium-пути зафиксированы в
`dev/architecture/360-panorama-packages.md` исходного репозитория.

## Автосохранение и локальное состояние

Данные `localStorage` не считаются доверенными или секретными. При восстановлении
проверяются версия payload, `projectId`/`novelId`, fingerprint сценария, наличие
сцены и диапазон индекса действия. Неизвестная или повреждённая структура
отклоняется. Авторский `engine.loadsafe=false` отключает только сравнение
fingerprint в режиме разработки, но не основные структурные проверки.

Пользователь устройства и код того же origin способны изменить или удалить
localStorage. Модель защищает runtime от исполнения сохранения как кода, но не
гарантирует подлинность прогресса и не использует сохранение для хранения тайн.

## Аудитор и размещение студенческих проектов

`tools/student-project-auditor.html` проверяет allowlist файлов, пути ресурсов,
сценарий, SVG, CSP и протокол мини-игр, CSS-панорамы и известные опасные
конструкции. Проверенный проект следует переносить в новый каталог, который
обслуживается только как статический.

Для полностью недоверенного проекта, особенно при наличии native bridge,
локальных секретов или соседних привилегированных приложений, браузерного
sandbox недостаточно. Требуется отдельный untrusted origin либо guest-процесс без
секретов и привилегированного моста.

## Релиз и цепочка поставки

Обычный CI выполняет ESLint, Node-тесты, Chromium/Firefox E2E, собирает ZIP и для
push в `main` проверяет распакованный кандидат в Microsoft Edge и Firefox на
Windows. Reusable workflow кандидата имеет только `contents: read`; права
публикации выдаются отдельной job после успешного кандидата.

Сборка использует строгий список обязательных runtime-файлов, проверяет полный и
update-ZIP, отсутствие developer-файлов и JS-пакетов панорам. Для каждого имени
архива создаётся и сразу проверяется SHA-256. Закреплённые сторонние библиотеки
контролируются через `dev/dependencies.json`, `NOTICE.md` и тесты зависимостей.

SHA-256 обеспечивает целостность только относительно checksum-файла. Без внешней
подписи он не доказывает подлинность, если злоумышленник одновременно заменил
архив и `.sha256` в скомпрометированном GitHub-аккаунте или Release.

## Предотвращаемые угрозы и остаточные риски

| Угроза | Основная защита | Остаточный риск |
| --- | --- | --- |
| Сеть, вложенный Worker или хранилище из сценария | В Worker скрыты глобальные API, но запрет неполон: `import()` и восстановление через прототипы обходят его | В direct авторский JS имеет права страницы; Worker до усиления CSP/API тоже не гарантирует запрет сети |
| Подмена прототипов и чрезмерная карта 360 | Копия с нулевыми прототипами и квоты | Допустимый большой объект всё ещё потребляет память |
| Выход пути за проект или внешний URL | Каноническая политика `assets/` и повторная проверка | Уязвимость браузерного декодера разрешённого формата |
| Доступ игры к родителю | Строгий iframe sandbox, Permissions Policy, frame-src родителя и отзыв сессии при повторном load | Нет полной изоляции сети и вычислений; WindowProxy не доказывает происхождение документа; возможна нагрузка на общий поток |
| Поддельный `gameResult` | `event.source`, `gameId`, `sessionId`, версия и одноразовая сессия | Скомпрометированная активная игра знает собственные идентификаторы |
| Исполняемый панорамный пакет | Только строгий CSS-формат; JS-пакеты запрещены | Большой допустимый CSS/WebGL-ресурс способен нагрузить устройство |
| Повреждённое сохранение | Проверка версии, проекта, fingerprint, сцены и индекса | Локальный пользователь может изменить сам прогресс |
| Неполный или повреждённый релиз | Проверка состава, smoke и SHA-256 | Компрометация доверенного CI/GitHub не закрывается checksum-файлом |

За пределами модели остаются:

- уязвимости и компрометация браузера, ОС, расширений и графического драйвера;
- замена доверенного runtime, библиотеки, инструмента или `license-key.js`;
- вредоносный код `story.js`, `story-example.js` или `story360.js` в режиме direct;
- прямой запуск недоверенного HTML, SVG или JavaScript вне официального runtime;
- хранение API-ключей, паролей и иных секретов в клиентских файлах;
- вредоносный статический проект, размещённый рядом с секретами на том же origin;
- гарантированная защита от исчерпания памяти и GPU на всех устройствах;
- сетевой перехват при размещении проекта по незащищённому HTTP;
- социальная инженерия, физический доступ и вопросы соблюдения лицензии.
